MARUS Unity 与 ROS2 通信使用指南

本文说明如何使用 grpc_ros_adapter 在 ROS2 Humble 中启动 gRPC server， 让 MARUS Unity 项目通过现有 ROS 协议发布传感器数据，并接收 ROS2 侧的推进器控制指令。

通信模型 编译 启动 Unity 配置 Topic 映射 控制示例 传感器示例 排错

1. 通信模型

MARUS 的 Unity 端不是直接连接 ROS2 topic。Unity 中的 RosConnection 会作为 gRPC client 连接外部进程；grpc_ros_adapter 则作为 ROS2 node 和 gRPC server，负责把 Unity 的 gRPC 消息转换成 ROS2 topic，或者把 ROS2 topic 转成 Unity 能理解的 gRPC 响应。

Unity / MARUS RosConnection, Sensor ROS wrappers, AUVRosController
grpc_ros_adapter gRPC server, protobuf services, ROS2 publishers/subscribers
ROS2 系统 ros2 topic, controller nodes, RViz, logging, navigation stack
方向 Unity 侧 Adapter 侧 ROS2 侧
传感器 client-streaming gRPC 推送 SensorStreaming service 接收并发布 订阅 sensor topic
推进器控制 AUVRosController 订阅 gRPC stream RemoteControl.ApplyForce 从 ROS2 topic 读 PWM 发布 Float32MultiArray
TF 发布或订阅 TF gRPC stream FrameService /tf 相关 topic
参数 请求地理原点等参数 ParameterServer ROS2 node parameters
默认 gRPC 地址是 0.0.0.0:30052。Unity 侧的 RosConnection.serverIP 和 serverPort 必须指向这个 adapter。

2. 编译 ROS2 包

ROS2 工作区路径：

2.1 准备环境

如果当前 shell 是 bash：

cd "${MARUS_ROS2_ROOT}"
source /opt/ros/humble/setup.bash

如果当前 shell 是 zsh：

cd "${MARUS_ROS2_ROOT}"
source /opt/ros/humble/setup.zsh
不要在 zsh 里 source setup.bash。zsh 应该使用 setup.zsh。

2.2 安装系统 Python 依赖

推荐使用 ROS/Humble 对应的 apt 包，避免用户目录里的 pip 包污染 ROS 的 Python 环境。 

sudo apt update
sudo apt install python3-grpcio python3-protobuf python3-yaml python3-numpy python3-opencv

2.3 colcon build

当前已经整理成标准 ROS2 workspace：两个包都在 src/ 下， 因此直接在工作区根目录编译即可。 

cd "${MARUS_ROS2_ROOT}"
rm -rf build install log
colcon build

看到下面类似输出即表示成功：

Summary: 2 packages finished

2.4 source install

bash：

source /install/setup.bash

zsh：

source /install/setup.zsh

2.5 验证包可见

ros2 pkg prefix grpc_ros_adapter
ros2 pkg prefix uuv_sensor_msgs
ros2 pkg executables grpc_ros_adapter
ros2 interface show uuv_sensor_msgs/msg/DVL

3. 启动 grpc_ros_adapter

3.1 推荐启动方式

使用 PYTHONNOUSERSITE=1 可以避免 ~/.local 里的 NumPy 2.x 干扰 ROS Humble 的 cv_bridge。

bash：

cd "${MARUS_ROS2_ROOT}"
source /opt/ros/humble/setup.bash
source install/setup.bash
PYTHONNOUSERSITE=1 ros2 launch grpc_ros_adapter ros2_server_launch.py

zsh：

cd "${MARUS_ROS2_ROOT}"
source /opt/ros/humble/setup.zsh
source install/setup.zsh
PYTHONNOUSERSITE=1 ros2 launch grpc_ros_adapter ros2_server_launch.py

3.2 直接 ros2 run

PYTHONNOUSERSITE=1 ros2 run grpc_ros_adapter server

正常启动时，终端会打印类似：

creating
[::]:30052
这表示 adapter 已经在 30052 端口等待 Unity 的 RosConnection 连接。

4. Unity / MARUS 场景配置

4.1 RosConnection

场景中需要一个 RosConnection 组件，配置如下：

字段 推荐值 说明
serverIP localhost 或 adapter 主机 IP Unity 和 adapter 同机时使用 localhost
serverPort 30052 必须和 ROS2 launch 参数一致
RealtimeSimulation true 实时仿真先保持默认即可

4.2 Vehicle 根节点

要让地址自动匹配，车辆根节点需要：

  • GameObject 名称稳定，例如 BlueROV2
  • tag 设置为 Vehicle
  • 挂载 ThrusterController
  • 挂载 AUVRosController
  • AUVRosController.thrusterController 指向同车的 ThrusterController

如果车辆名是 BlueROV2，Unity 的 AUVRosController 会订阅 gRPC 地址： 

BlueROV2/pwm_out

adapter 会把该地址转换为小写 ROS2 topic：

/bluerov2/pwm_out

4.3 传感器

每个传感器通常需要“传感器本体组件 + 对应 ROS wrapper 组件”。例如：

Unity 传感器本体 Unity ROS wrapper ROS2 topic 示例
ImuSensor ImuROS /bluerov2/imu_link
DepthSensor DepthSensorROS /bluerov2/depth_link
GnssSensor GnssROS /bluerov2/gnss_link
CameraSensor CameraSensorROS /bluerov2/front_camera
RaycastLidar RaycastLidarPointCloud2ROS /bluerov2/lidar_link

5. Topic 映射规则

MARUS wrapper 会发出一个 gRPC address。adapter 的规则很直接：

  • 把地址转成小写
  • 如果没有 / 前缀，就补成绝对 topic
  • 按消息类型创建 ROS2 publisher 或 subscriber
Unity gRPC address ROS2 topic 方向
BlueROV2/pwm_out /bluerov2/pwm_out ROS2 -> Unity
BlueROV2/imu_link /bluerov2/imu_link Unity -> ROS2
BlueROV2/front_camera /bluerov2/front_camera Unity -> ROS2
BlueROV2/front_camera/compressed /bluerov2/front_camera/compressed Unity -> ROS2

6. ROS2 控制 Unity 推进器

6.1 发送一次 PWM

假设车辆名是 BlueROV2，并且 ThrusterController.thrusters 有 4 个推进器： 

ros2 topic pub --once /bluerov2/pwm_out std_msgs/msg/Float32MultiArray \
  "{data: [0.2, 0.2, 0.2, 0.2]}"

6.2 持续发布 PWM

ros2 topic pub -r 20 /bluerov2/pwm_out std_msgs/msg/Float32MultiArray \
  "{data: [0.15, 0.15, 0.15, 0.15]}"
PWM 数组顺序必须和 Unity 中 ThrusterController.thrusters 列表顺序一致。 建议每次发布完整长度数组。

6.3 Python 控制节点最小例子

#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from std_msgs.msg import Float32MultiArray


class PwmController(Node):
    def __init__(self):
        super().__init__("marus_pwm_controller")
        self.pub = self.create_publisher(Float32MultiArray, "/bluerov2/pwm_out", 10)
        self.timer = self.create_timer(0.05, self.tick)

    def tick(self):
        msg = Float32MultiArray()
        msg.data = [0.15, 0.15, 0.15, 0.15]
        self.pub.publish(msg)


def main():
    rclpy.init()
    node = PwmController()
    rclpy.spin(node)
    node.destroy_node()
    rclpy.shutdown()


if __name__ == "__main__":
    main()

8. 推荐操作顺序

  1. 启动 ROS2 环境并 source adapter install。
  2. 运行 PYTHONNOUSERSITE=1 ros2 launch grpc_ros_adapter ros2_server_launch.py。
  3. 打开 Unity 场景，确认 RosConnection 指向 localhost:30052。
  4. 进入 Play 模式，观察 adapter 终端是否保持运行。
  5. 运行 ros2 topic list，确认 Unity 传感器 topic 出现。
  6. 发布 /bluerov2/pwm_out，确认 Unity 车辆推进器响应。

9. 常见问题

9.1 source setup.bash 报 setup.sh 不存在

你可能在 zsh 里 source 了 bash 脚本。zsh 使用： 

source /opt/ros/humble/setup.zsh
source install/setup.zsh

9.2 cv_bridge / NumPy 报 _ARRAY_API not found

这是用户目录里的 NumPy 2.x 干扰了 ROS Humble 的 apt 版 cv_bridge。 启动 adapter 时加： 

PYTHONNOUSERSITE=1 ros2 launch grpc_ros_adapter ros2_server_launch.py

9.3 Unity 连接不上 ROS Server

  • 确认 adapter 终端打印 [::]:30052。
  • 确认 Unity RosConnection.serverPort 是 30052。
  • 同机运行时 serverIP 用 localhost。
  • 跨机器运行时，确认防火墙允许 TCP 30052。

9.4 发布 PWM 后 Unity 没反应

  • 确认 Vehicle GameObject 名是否真的是 BlueROV2。
  • 确认 ROS2 topic 使用小写：/bluerov2/pwm_out。
  • 确认车辆根节点 tag 是 Vehicle。
  • 确认 AUVRosController.thrusterController 已绑定。
  • 确认 PWM 数组长度和推进器数量匹配。

9.5 colcon 找不到 uuv_sensor_msgs

在标准工作区中，uuv_sensor_msgs 应位于 src/uuv_sensor_msgs。 先确认包可见，再从工作区根目录编译： 

cd "${MARUS_ROS2_ROOT}"
colcon list
colcon build

9.6 端口被占用

ss -ltnp | grep 30052

如果已有 adapter 实例在运行，先停止旧进程，或者修改 launch/ros2_server_launch.py 中的 server_port 并同步修改 Unity。
