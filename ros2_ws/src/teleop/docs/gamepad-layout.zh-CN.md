# 飞智冰原狼 2 手柄按键布局与输入值说明

> 适用设备：飞智冰原狼 2（Flydigi Direwolf 2）
> 文档重点：实体按键布局、XInput 输入信号、摇杆/扳机数值范围、特殊按键行为，以及 Switch / DInput 模式差异。

---

## 1. 手柄按键总览

飞智冰原狼 2 采用 Xbox 风格的非对称摇杆布局，并额外提供 FN 功能键与两颗背键 M1 / M2。

如果按“可按下的物理部件”计数，并将十字键作为一个整体，手柄共有 **17 个可按压部件**：

| 类型           |         数量 | 说明               |
| -------------- | -----------: | ------------------ |
| ABXY           |            4 | A、B、X、Y         |
| 十字键         |            1 | 八向十字盘         |
| 摇杆按压       |            2 | L3、R3             |
| 肩键           |            2 | LB、RB             |
| 扳机           |            2 | LT、RT，支持模拟量 |
| 功能键         |            2 | SELECT、START      |
| 中央功能键     |            2 | FN、HOME           |
| 背键           |            2 | M1、M2             |
| **合计** | **17** | 不含模式切换拨杆   |

如果将十字键的上、下、左、右分别视为独立逻辑输入，则可以看作 **20 个按压方向/动作**。

> 背面的 PC / 蓝牙 / NS 模式切换拨杆属于模式选择机构，不视为普通游戏输入按键。

---

## 2. 实体按键布局

手柄正面大致布局如下：

```text
                 LT   LB                 RB   RT


            左摇杆        SELECT   START         Y
                                               X   B
               十字键          FN  HOME           A
                             右摇杆


背面：              M1      模式拨杆      M2
```

布局特点：

- 左摇杆位于左上方。
- 十字键位于左下方。
- ABXY 位于右上方。
- 右摇杆位于右下方。
- SELECT / START 位于中央区域。
- FN 与 HOME 位于中央偏下。
- M1 / M2 位于手柄背面，供中指或无名指触发。
- LT / RT 位于顶部外侧。
- LB / RB 位于 LT / RT 前方。

## 3. PC XInput 模式输入定义

在 Windows PC 的 XInput 模式下，冰原狼 2 可按 Xbox 类控制器方式读取。

XInput 中主要有三类输入：

1. 数字按键：通过 `wButtons` 位掩码输出。
2. 模拟扳机：LT / RT 输出 0～255。
3. 模拟摇杆：LX / LY / RX / RY 输出 16 位有符号整数。

---

## 4. 数字按键的 XInput 值

| 物理按键  | XInput 名称        | 十六进制值 | 信号类型 |
| --------- | ------------------ | ---------: | -------- |
| 十字键 ↑ | `DPAD_UP`        | `0x0001` | 数字     |
| 十字键 ↓ | `DPAD_DOWN`      | `0x0002` | 数字     |
| 十字键 ← | `DPAD_LEFT`      | `0x0004` | 数字     |
| 十字键 → | `DPAD_RIGHT`     | `0x0008` | 数字     |
| START     | `START`          | `0x0010` | 数字     |
| SELECT    | `BACK`           | `0x0020` | 数字     |
| L3        | `LEFT_THUMB`     | `0x0040` | 数字     |
| R3        | `RIGHT_THUMB`    | `0x0080` | 数字     |
| LB        | `LEFT_SHOULDER`  | `0x0100` | 数字     |
| RB        | `RIGHT_SHOULDER` | `0x0200` | 数字     |
| A         | `A`              | `0x1000` | 数字     |
| B         | `B`              | `0x2000` | 数字     |
| X         | `X`              | `0x4000` | 数字     |
| Y         | `Y`              | `0x8000` | 数字     |

数字键通常只有两个状态：

```text
松开 = 0
按下 = 1
```

在 XInput 中，多个按键可以同时置位。

例如：

```text
↑       = 0x0001
→       = 0x0008
↑ + →   = 0x0009
```

因此十字键斜方向实际上是两个方向 bit 同时置位。

---

## 5. 摇杆轴输出范围

冰原狼 2 的左右摇杆在 XInput 中分别对应四个 16 位有符号轴：

| 轴       | XInput 字段  | 原始范围            |
| -------- | ------------ | ------------------- |
| 左摇杆 X | `sThumbLX` | `-32768 ～ 32767` |
| 左摇杆 Y | `sThumbLY` | `-32768 ～ 32767` |
| 右摇杆 X | `sThumbRX` | `-32768 ～ 32767` |
| 右摇杆 Y | `sThumbRY` | `-32768 ～ 32767` |

### 5.1 X 轴方向

```text
最左          中心          最右
-32768          0          +32767
```

### 5.2 Y 轴方向

```text
最下          中心          最上
-32768          0          +32767
```

即：

- X 轴负值：向左。
- X 轴正值：向右。
- Y 轴负值：向下。
- Y 轴正值：向上。

程序中经常将其归一化到约：

```text
-1.0 ～ +1.0
```

例如：

```text
-1.0  ≈ 最左 / 最下
 0.0  ≈ 中心
+1.0  ≈ 最右 / 最上
```

---

## 6. LT / RT 扳机输出范围

LT 和 RT 在 XInput 模式下是两个独立的 8 位无符号模拟量。

| 扳机 | XInput 字段       | 原始范围     |
| ---- | ----------------- | ------------ |
| LT   | `bLeftTrigger`  | `0 ～ 255` |
| RT   | `bRightTrigger` | `0 ～ 255` |

对应关系约为：

```text
完全松开       = 0
半按           ≈ 127 / 128
完全按下       = 255
```

程序中常归一化为：

```text
0.0 ～ 1.0
```

例如：

```text
0.0 = 完全松开
0.5 = 约半按
1.0 = 完全按下
```

## 7. XInput 输入数据结构概览

从程序读取角度，可以将冰原狼 2 的主要 XInput 输入概括为：

```text
Buttons : uint16 位掩码
LT      : uint8，范围 0..255
RT      : uint8，范围 0..255
LX      : int16，范围 -32768..32767
LY      : int16，范围 -32768..32767
RX      : int16，范围 -32768..32767
RY      : int16，范围 -32768..32767
```

其中标准 XInput 层可以直接识别：

- 14 个主要数字输入；
- 2 个独立模拟扳机；
- 4 个摇杆模拟轴。

## 8. M1 / M2 背键

M1 和 M2 是冰原狼 2 的额外背键，但它们并不属于微软标准 XInput 按键位表中的独立按键。

通常情况下：

```text
M1 / M2
    ↓
映射到已有按键或宏
    ↓
应用程序收到被映射后的普通按键信号
```

例如将 M1 映射成 A：

```text
按下 M1
→ 手柄输出 A
→ XInput 中表现为 A = 0x1000
```

因此，在标准 `XInputGetState()` 数据中，一般不会看到一个独立的“M1”或“M2”字段。

如果需要把 M1 / M2 当作真正独立输入读取，需要研究设备私有 HID 报告或飞智驱动层，而不能仅依赖标准 XInput。

---

## 9. FN 功能键

FN 主要作为手柄内部功能修饰键使用。

典型用途包括：

- 连发设置；
- 连发频率调整；
- 震动设置；
- 与其他按键组合执行手柄内部功能。

FN 不属于标准 `XINPUT_GAMEPAD.wButtons` 定义中的独立游戏按键。

因此在标准 XInput API 中：

```text
通常无法直接获得：
FN = 0 / 1
```

如果需要检测 FN 本身，需要进一步读取设备的私有 HID / 驱动数据。

---

## 10. HOME 键

HOME 键主要用于：

- 手柄开机；
- 连接；
- Home / Guide 类系统操作。

标准公开的 `XINPUT_GAMEPAD.wButtons` 并没有正式提供可直接使用的 Guide / Home bit。

因此，在普通 `XInputGetState()` 中不应假定某个保留位一定代表 HOME。

如果程序必须读取 HOME 键，应考虑：

- Windows Gaming Input；
- Raw HID；
- SDL / HIDAPI；
- 厂商私有协议；
- 其他能够暴露 Guide/Home 的控制器 API。

---

## 11. Switch 模式键位对应关系

冰原狼 2 的实体 ABXY 采用 Xbox 风格标识，而 Nintendo Switch 的 ABXY 逻辑位置不同。

在 Switch / NS 模式下，主要对应关系为：

| 冰原狼 2 实体键 | Switch 逻辑输入   |
| --------------- | ----------------- |
| A               | B                 |
| B               | A                 |
| X               | Y                 |
| Y               | X                 |
| SELECT          | `-`             |
| START           | `+`             |
| HOME            | HOME              |
| FN              | Screenshot / 截图 |

因此：

```text
实体键帽名称 ≠ Switch API 中的逻辑名称
```

编写跨平台程序时应特别注意这一点。

## 12. DInput 模式注意事项

冰原狼 2 也支持 DInput，但 DInput 下的轴编号和取值方式可能与 XInput 不同。

尤其要注意 LT / RT。

在传统 DirectInput 兼容模式中，两个独立扳机有可能被合并到一个 Z 轴：

```text
       LT
        ↑
负方向 ← 中心 → 正方向
                  ↓
                  RT
```

实际方向定义取决于具体驱动和软件接口。

因此如果目标是在 Windows 上准确读取：

- 独立 LT；
- 独立 RT；
- Xbox 风格按键；

优先建议使用 **XInput**。

## 13. 各类输入的推荐归一化形式

对于游戏、机器人控制、数据采集等程序，可以将各输入统一转换为以下形式：

| 输入类型 | 原始范围      | 推荐归一化 |
| -------- | ------------- | ---------- |
| 数字按键 | 0 / 1         | 0 / 1      |
| LX / LY  | -32768～32767 | -1.0～1.0  |
| RX / RY  | -32768～32767 | -1.0～1.0  |
| LT       | 0～255        | 0.0～1.0   |
| RT       | 0～255        | 0.0～1.0   |

示例：

```text
A      = 1
B      = 0

LX     = -0.63
LY     = +0.18

RX     = +0.02
RY     = -0.95

LT     = 0.00
RT     = 0.72
```

## 14. 死区与实际中心值

虽然 XInput 的理论中心值为 0，但真实手柄的摇杆可能出现轻微漂移。

例如：

```text
理论中心：
LX = 0
LY = 0

实际静止时可能出现：
LX = 213
LY = -487
```

因此程序通常需要设置死区。

微软 XInput 常见默认死区参考值包括：

```text
左摇杆死区： 7849
右摇杆死区： 8689
扳机阈值：   30
```

需要注意：

- 这些数值是 XInput 常见参考值，不代表冰原狼 2 必须使用相同死区。
- 飞智驱动中的摇杆曲线、死区、校准设置可能改变最终输出。
- 如果应用对精度敏感，应实际采样该手柄的中心漂移和最大行程。

## 15. 信号类型总结

| 控制器部件     | 类型       | XInput 范围/结果               |
| -------------- | ---------- | ------------------------------ |
| A / B / X / Y  | 数字       | bit 0 / 1                      |
| 十字键         | 数字       | 4 个方向 bit                   |
| LB / RB        | 数字       | bit 0 / 1                      |
| L3 / R3        | 数字       | bit 0 / 1                      |
| START / SELECT | 数字       | bit 0 / 1                      |
| LT / RT        | 模拟       | 0～255                         |
| 左摇杆 X/Y     | 模拟       | -32768～32767                  |
| 右摇杆 X/Y     | 模拟       | -32768～32767                  |
| M1 / M2        | 映射/宏    | 通常输出映射后的已有信号       |
| FN             | 内部功能键 | 标准 XInput 无独立 bit         |
| HOME           | 系统功能键 | 标准公开 XInput 位表无正式字段 |

## 16. 如果要读取“原始 HID 数据”

如果目标不是普通游戏输入，而是直接读取 USB / 2.4G / 蓝牙 HID 报告，则还需要进一步确定：

1. 连接方式：

   - USB 有线；
   - 2.4G 接收器；
   - 蓝牙。
2. 当前模式：

   - XInput；
   - DInput；
   - Switch / NS。
3. 目标接口：

   - Windows Raw Input；
   - HIDAPI；
   - Linux `hidraw`；
   - SDL；
   - ESP32 USB Host；
   - STM32 USB Host；
   - 其他 HID Host。

不同模式下 HID Report Descriptor、Report ID、字节偏移和 bit 位定义可能不同，因此不能直接把 XInput 数值表当作 USB HID 报告格式。

如果需要精确到字节级，应进一步获取：

```text
Report ID
Byte Offset
Bit Offset
Logical Minimum
Logical Maximum
Usage Page
Usage
```

最终可以整理成类似：

```text
Byte 0    : Report ID
Byte 1    : Buttons bit 0..7
Byte 2    : Buttons bit 8..15
Byte 3-4  : LX
Byte 5-6  : LY
...
```

但这部分必须以实际 HID 描述符或抓包结果为准。

## 18. 一句话总结

在 PC XInput 模式下，可以把飞智冰原狼 2 看成：

```text
14 个标准数字游戏输入
+ 2 个 0～255 的独立模拟扳机
+ 4 个 -32768～32767 的摇杆轴
+ M1 / M2 映射背键
+ FN / HOME 等非标准 XInput 功能键
```

对于普通 PC 程序开发，优先使用 **XInput**；如果需要读取 M1、M2、FN、HOME 或精确 HID 字节布局，则需要进一步分析设备私有 HID 协议。
